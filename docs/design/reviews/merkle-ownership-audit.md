## Reusable versus ArkLib-specific

VCVio already owns the reusable tree, addressed query model, pruned batch proof, extraction state, shared-ROM experiment, resource predicates, and finite counting theorem. In particular `Adversary.IsAdversaryPrefixQueryBound` charges every malicious commitment and terminal-opening query, while `HasVerifierQueryBound` charges every output claim's honest verification cost and quantifies over every private/extractor state, even unreachable ones (`ResourceBounds.lean:184–213`). An unbounded pure list of claims makes this second premise essential. `claimsQueryCount_le_openingCount_mul` offers one way to establish it (`ResourceBounds.lean:164–173,215–235`). The node budget premises are per-tag, total (`rounds * perCheckpoint ≤ nodeBudget`), and checkpoint count (`rounds ≤ checkpointCount`) in both VCVio `StrongBound.lean:518–535` and ArkLib `MerkleTerminalBatch.lean:1322–1343` / `MerkleAdaptiveTerminal.lean:721–742`. The numerator is the supremum over fresh-prefix misses of `choose 2 + min nodeBudget (2*misses + checkpointCount) * (queryBound + verifierOverhead)` (`Potential.lean:67–77`), divided by `Nat.card Y`; avoid calling it just a generic collision error.

ArkLib-specific material is public occurrence indexing (`Fin rounds`), matching a submitted selector to a verifier plan, collecting ordered selected values, running a native `Interaction.Oracle` sender/verifier strategy, and coupling that execution to the VCVio game (`MerkleTerminalBatch.lean:31–48,145–181,240–271,665–687`). The adapter is a suitable local owner for these notions because they refer to ArkLib's protocol semantics. `MerkleAdaptiveTerminal.QueryProgram` is a terminal decision program, not an interactive verifier query protocol: it takes `List Y` answers into its continuation, and the actual protocol continues to use one list-valued terminal prover message (`MerkleAdaptiveTerminal.lean:30–37,124–153`; `MerkleTerminalBatch.lean:69–74`). The ideal decision is a pure observation of checkpoint-time extracted values, with missing cells filled by an explicit fallback (`MerkleTerminalBatch.lean:201–229`; `MerkleAdaptiveTerminal.lean:97–122`). The suffix-erasure theorems identify **Boolean event probabilities**, not final oracle-cache states (`MerkleTerminalBatch.lean:1208–1229`; `MerkleAdaptiveTerminal.lean:678–716`).

I see no second ArkLib Merkle primitive or copied VCVio security game. The long ArkLib batch module proves source/native/owner coupling and program-specific acceptance, rather than duplicating VCVio's extraction invariant or counting proof. A small possible upstream candidate is generic traversal/flattening of VCVio's `SelectedValues` (the ArkLib `selectedValuesList` at `MerkleTerminalBatch.lean:50–56`), but this alone is not evidence of a migration need; leave it local until another client needs that API. If a real client needs live requests, encoded payload extraction, a generic trace transducer, or a multi-root cap theorem, first specify that client and add the reusable theorem at the relevant owner. Do not advertise the present raw-digest adapter as covering VCVio's richer Hashing/HashForest abstractions.

VCVio's own `docs/reading/internal-duplication.md:25–32` says that earlier presentation is gone and `Addressed/` layers on `Inductive/`. Suggested replacement: “Merkle construction and security live upstream in VCVio under `VCVio/CryptoFoundations/MerkleTree/`: `Inductive/` provides typed binary trees and pruned openings, `Addressed/` specializes node queries, `MultiExtractability/` owns shared-ROM checkpoint extraction, and `Hashing/` and `HashForest/` provide richer hashing shapes. ArkLib's `Interaction/Oracle/MerkleTerminalBatch.lean` and `MerkleAdaptiveTerminal.lean` adapt the VCVio theorem to native terminal interactions.”
2. `docs/design/00-current-status.md:75,358–368` and `05-roadmap.md:434–449` already give the right high-level status. Preserve their distinction between an available restricted adapter and the deferred compiler/BCS/FRI/Spartan migrations. If a README claims merely “Merkle Trees” (`README.md:35`), clarify that ArkLib **uses VCVio's** Merkle primitives and owns native Interaction adapters, rather than appearing to own a general primitive implementation.
3. State the precise limit in public summaries: fixed and causal terminal plan, one terminal opening batch, raw-digest leaves, uniform finite response measure and explicit adversarial/verifier/node/checkpoint budgets, plus a separately proved ideal acceptance bound `hideal` for the `η + error` corollary (`MerkleAdaptiveTerminal.lean:760–784`; batch analog `MerkleTerminalBatch.lean:1361–1388`).
