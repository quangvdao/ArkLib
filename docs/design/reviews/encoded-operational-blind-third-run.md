## Literal mathematical content

`StrictCodec K D` consists of `encode : K → D` and `decode : D → Option K`, with both `decode (encode k) = some k` and `decode d = some k → encode k = d`. Thus encoding is injective and every successful decode is exactly an encoded value. The code derives a bijection `D ≃ K ⊕ OffImage`, where `OffImage` is the subtype of values whose decode is `none`. This is a strong canonical-decoding assumption: a decoder that accepts a second representation for one key cannot inhabit this structure. Neither `K` nor `D` is required to be nonempty.

For arbitrary types `K,D,C,A`, a strict codec, decidable equality on `D`, a `SampleableType C`, and **any** `OracleComp (unifSpec + (D →ₒ C)) A` program, `routeProgram` simulates its uniform-coin queries and its encoded-oracle queries over a native `(K →ₒ C)` oracle. A coin query is passed through and produces no oracle-log entry. An encoded query `d` with `decode d = some k` queries native key `k`, returns its answer, and appends `(d,answer)` to the external log. An off-image query checks a separate `D`-keyed cache: a hit returns its cached answer, while a miss independently samples `$ᵗ C`, stores the answer at `d`, and returns it. Either off-image case appends `(d,answer)` to the external log. The default off-image cache is empty. The program can adapt to answers and coin outcomes and can repeat queries; its declared interface has no direct native-key oracle access.

`mergeCache native off` is the encoded-oracle cache whose value at `d` is `native k` on a successful decode to `k`, and `off d` otherwise. Image entries in `off` are ignored. The cache lemmas show empty-cache preservation and that native image updates and off-image updates correspond to updates of this merged cache. `routedRawRun` executes the routed program through a cached native random oracle; `routedLoggedRun` returns its answer/external log and merged final cache. For **all** initial native and off-image caches, `routedLoggedRun_eq_randomOracleLoggedRun` equates that result with running the original encoded-oracle program through the standard cached, logged random oracle from the merged initial cache. `routeProgram_externalProjection` states the corresponding equality after a native logged run is projected to its program answer, external log, and merged cache, discarding the native log and separate cache representation. These are equalities of the specified probabilistic computations, including the logged external query/answer trace and final projected cache; they are not an equality of the native and external logs themselves.

`decodeImageLog` walks an external encoded-oracle log in order, removes entries whose keys decode to `none`, and replaces each remaining `(d,answer)` by `(decode d,answer)`. For every supported result of a native logged execution of the routed program, `routeProgram_nativeLog` states that its **native** query log equals `decodeImageLog` of its **external** query log. This includes repeated calls and cache hits. The statement needs membership in the support of the specified run, so it does not assert the relation for arbitrary fabricated result tuples. The derivation relies on the fact that off-image sampling is a uniform `ProbComp` sample rather than a native-key query.

The imported `QueryLog` is a list of dependent key/answer pairs. The imported `withLogging` logs **every** oracle query after it returns, even if the cache supplied the answer. `freshKeysOfLog` maps a log to the finite set of keys that occur anywhere in it; “fresh” here means distinct *queried keys*, not cache misses or first-time random samples. Uniform-coin queries are absent from these oracle logs. `freshQueryCharge weight log` sums `weight` once over each such distinct key. `expectedFreshQueryCharge program weight` integrates that charge over a logged random-oracle run with an **empty initial cache**.

`freshImageKeys_card_le` proves, for every external log, that the number of distinct decoded image keys does not exceed the number of distinct external keys. `routeProgram_nativeCharge_le` applies this inequality to the two logs of each supported routed run, allowing arbitrary initial native and off-image caches. `expectedNativeFreshKeys_le_external` then states, for an arbitrary program and **empty** caches on both runs, that the expected distinct native-key count is at most the expected distinct external-key count. Both sides count logged keys, including keys already cached within a run.

`encodedWeight weight d` is `weight k` when `decode d = some k`, and `0` when `decode d = none`. `freshImageCharge_le` proves, for every log and arbitrary `weight : K → ENNReal`, that the distinct-key charge of the decoded image log is at most the external log's charge under `encodedWeight`. `expectedNativeCharge_le_external` gives the analogous expectation inequality for an arbitrary encoded-oracle program, with empty initial caches. The weights are extended nonnegative reals, so zero and infinity are admitted; no separate monotonicity, finite-budget, or summability premise is imposed. Unlike the count theorem, this external weighted side charges off-image queries zero. The statement provides a weak inequality; it does not state a converse or equality.

In `EncodedFibre`, the earlier `StateRestoration` definitions make `Key Input Salt rounds` the recursively tagged round-query key, and `key.Challenge` its round-dependent challenge type; `Table` is the dependent function assigning an answer to every key, and `oracleSpec` is the corresponding dependent-output oracle. A `Round` stores finite, nonempty, sampleable challenge data. `CommonChallenge Input Salt C rounds` requires an equivalence `key.Challenge ≃ C` **for every key**. `tableEquiv` converts complete dependent tables to and from `Key → C` tables pointwise; `cacheEquiv` does the same for optional cache entries; `toCommonLog` maps each logged answer through that key's equivalence. `commonQueryImpl` passes coin queries through and maps each dependent native-oracle answer into `C`; `simulateNative` applies it to an arbitrary common-answer program. With an additional `SampleableType C`, `evalDist_fibre_uniform` says that mapping a uniform sample from any particular `key.Challenge` through its equivalence has the same distribution as a uniform sample from `C`. The class of sampleable types is finite and nonempty by imported instances. The uniformity theorem is per key, with a locally discrete measurable space; it does not itself assert equality of whole adaptive program runs or of jointly sampled tables.

## Scope boundaries and possible vacuity

These modules do not declare a bad event, success probability, extractor, security error, or an encoded version of a state-restoration soundness theorem. Their quantitative conclusions compare query charges for arbitrary encoded-oracle programs; a later application must supply the connection from the program and its event to any particular security game, as well as a bound that uses these charges. No theorem in these five modules composes `CommonChallenge.simulateNative` or its table/cache conversions with `StrictCodec.routeProgram`, its log relation, or its charge inequalities. The `CommonChallenge` structure supplies the pointwise answer equivalences but does not construct or assume a codec between native `Key` and external `D`.

The assumptions are satisfiable in ordinary finite cases, but some quantified cases are vacuous or degenerate. With no rounds, `Key Input Salt []` is empty, so the `CommonChallenge.fibre` obligation and its per-key uniformity claim have no key instances; table and cache equivalences then concern empty-domain functions. A strict codec with empty `K` has no image keys, and its native charge is zero for every program; all encoded queries are off-image. If `D` is empty, there are no encoded queries. `SampleableType C` prevents an empty answer type in the reduction. The exact `StrictCodec` round-trip laws exclude noncanonical accepted encodings; they are premises, not conclusions about an arbitrary parser.
