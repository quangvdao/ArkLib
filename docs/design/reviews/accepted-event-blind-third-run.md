## Main declaration

`Interaction.Oracle.FiatShamir.fsNARGFailure_eq_actual_singleSaltAccepted` is universally parameterized by a list of rounds; types `Statement`, `GlobalSalt`, `WitIn`, and `Output`; a statement-only guard schedule; Boolean acceptance and optional-output observation functions on a statement and full execution path; a knowledge state and round extractor indexed by the **statement–global-salt pair**; a seed from `Unit` to the terminal witness type; a witness map; an input relation `relIn ⊆ Statement × WitIn`; an output language `langOut ⊆ Output`; and a prover `P`. Its explicit typeclass assumptions are `VCVCompatible GlobalSalt`, compatible and sampleable challenge types, decidable equality of each message type and of `Statement`, and `Finite Statement`. These are parameters and assumptions, not premises proving any relation between the acceptance test, observation, knowledge state, and extractor.

The prover is an oracle computation with query interface `((OracleSpec.ofPFunctor 0 + fsChallengeOracle (Statement × GlobalSalt) (legacySpec rounds)) + unifSpec)`. It can make hash/challenge and uniform coin queries before returning `(statement, (globalSalt, messages))`. `FSSaltedProof` is literally `GlobalSalt × (legacySpec rounds).Messages`. The one salt is an output chosen by the prover, and the code places no requirement that the prover sample it uniformly. The random-oracle input contains the pair `(statement, globalSalt)` and a protocol-message prefix; the bridge's native key representation uses `Input × message × PUnit` at the current round and carries prior messages in nested keys. Thus the chosen global salt separates hash inputs because it is part of `Input`, while `PUnit` is the per-round salt. The prover may query the oracle on other statement–salt pairs before selecting its final proof.

The theorem equates two **failure-event probabilities**, for every such choice of parameters and prover.

* On the left, `adaptiveNARGKnowledgeSoundnessExpWithCoins` runs `P` against a finite-table-backed challenge oracle and the given uniform-coin implementation, then runs `Verifier.singleSaltFiatShamir` using a pure native legacy verifier whose observation is `matchedLegacyObserve`, and then runs `fsSRDelegatingNargExtractor` built from the native backward legacy extractor. The experiment returns `(statement, optional extracted witness, optional verifier output)`. `nargKSFailEvent relIn langOut` requires a verifier output in `langOut` and either no extracted witness or an extracted witness outside `relIn` for the statement. In this concrete instantiation the native backward extractor returns `some` of a witness-map image, so its absent-witness branch is not the operative case.
* On the right, `legacySingleSaltAdversary rounds (srInducedProverKS P)` simulates the same prover queries through the native random-oracle interface and produces an optional selected `(statement, (globalSalt, public messages), Unit)`. `singleSaltAcceptedExecution` records the adversary log, completes the selected messages by querying the random oracle round by round, stops with `none` when a guard fails, and filters a completed path to `none` when `accepts` is false. `randomOracleLoggedRun ... ∅` starts with an empty oracle cache and returns the execution result, query log, and final cache. The event projects `joint.1.1.1`: only the optional `(statement–salt pair, full path, Unit)` is used; logs and cache are not event arguments. `badStoppedRelation` is false on `none`. On `some (z,path,())`, it asserts (with `Z = Set.univ`) that `legacyOutputRelation (fun z path => observe z.1 path) (unitOutputRelation langOut)` holds and that the round extractor's mapped extracted witness fails `legacyInputRelation state witnessMap (relInSalted relIn)`. Expanded, the output part says `observe z.1 path = some output` for some `output ∈ langOut`; the input failure says `(z.1, witnessMap z (extractWitness path (seed z path ()))) ∉ relIn`. The salt is discarded by these two *relations*, though `state`, `extractor`, and `seed` can depend on it.

`matchedLegacyObserve` returns `observe statement path` exactly when `guardsPassPath` and `accepts` are both true; otherwise it returns `none`. The lifted guard schedule and acceptance/observation functions on the right explicitly project `z.1`, so their tests are salt-independent. A guard can depend on the current message and on earlier oracle challenges through the recursively chosen guard schedule. `guardsPassPath` checks all guards along a completed path. There is no requirement that `observe` itself be Boolean or total; `none` excludes the failure event. For an empty round list, the guard conjunction is true and completion makes no round challenge query.

## Supporting equalities and boundary

`fsKSShared_failure_eq` in `ArkLib.OracleReduction.FiatShamir.Legacy.SingleSalt` is the NARG-to-state-restoration failure-probability equality used first. Its `relInSalted` lifts the input relation by dropping the salt, and `unitOutputRelation` tests only membership of the output in `langOut`. `srInducedProverKS` maps a salted NARG proof to restoration input `(statement,salt)`, messages, and `Unit`. The later bridge, `coinKSExperimentProb_eq_actual_singleSaltAccepted`, replaces the state-restoration experiment by the logged accepted single-salt execution. At a fixed table, `stoppedPath` is the full completed path filtered by all guards, and a second filter applies `accepts`; this is why the value-level and event-level formulas agree. `singleSaltAccepted_lazy_eq_eager` equates the distributions of the **full logged result** under a lazy random oracle and an independently sampled finite table, provided the stated finiteness, decidable-equality, and table-sampling instances exist. The final event then projects the value from that full result.

No query bound, error estimate, local boundedness, prover preservation, terminal-state validity, or input/output law appears in this equality theorem. It is an identification of events, not a soundness inequality. In particular, `badStoppedRelation` only tests the output relation and failure of the extracted input relation; it does **not** itself assert that the terminal seed satisfies a terminal-state predicate. The theorem can have zero failure probability for uninformative choices such as `accepts = false`, a guard that always fails, an observation that always returns `none`, or an empty output language. There is no positivity or non-vacuity hypothesis. Conversely, the statement does not quantify over all predicates implicitly: guards, accepts, observe, state, extractor, seed, witness map, relations, and `P` are explicit arbitrary parameters.
