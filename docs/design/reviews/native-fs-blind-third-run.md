## The actual single-salt program

`SaltedProof GlobalSalt rounds` is `GlobalSalt × PublicMessages rounds`. A `SingleSaltAdversary` is any `OracleComp` with uniform and hash oracles returning `none` or `some (statement,(salt,messages),witness)`. Its hash oracle is `oracleSpec (Statement × GlobalSalt) PUnit rounds`: the selected *one global salt* is part of the statement component of each completion key, while the per-round salt type is the unit type. The adversary chooses the salt as part of its output; the theorem does not sample or constrain its distribution.

`singleSaltExecution rounds guards adversary` first runs `adversary.withQueryLog`. On `none` it returns `none` with that attached log. On `some`, it runs `publicStoppedVerify rounds guards (statement,salt) messages` through the same hash oracle and maps a successful path to `((statement,salt),path,witness)`. This is the *public strategy execution*: `guardedPublicProtocol` has a public sender message, checks the guard, and either ends immediately or exposes a public receiver challenge. The scripted prover supplies the adversary's message sequence. The guarded public verifier queries the hash key for each passed round; `acceptedPath` decodes a full restoration path only when every guard passes. A failed prefix guard yields `none` before that round's hash query. The next guard schedule can depend on the preceding hash challenge.

`PublicExecutionCorrespondence.publicStoppedVerifyWith_eq_mapped` and `StoppedCompletionTransport.publicStoppedVerify_eq_stoppedComplete` are proved equalities of oracle programs (using `withUnitSalts`), with no security or distribution hypothesis. `singleSaltExecution_eq_stopped` consequently identifies the actual program with randomized stopped completion of `inducedAdversary adversary`; `inducedAdversary` only rearranges `some (statement,(salt,messages),witness)` into `some ((statement,salt),withUnitSalts messages,witness)`. These equalities are code-level transport results, not additional assumptions in the security theorem.

`singleSaltVerify` further filters a completed path by `accepts (statement,salt) path`. `singleSaltAcceptedExecution` applies the corresponding filter to `singleSaltExecution`'s selected result. `singleSaltAcceptedExecution_eq_verify` proves the filter is equivalent to running `singleSaltVerify` after adversary selection. If the adversary selects `none`, a prefix guard fails, or terminal `accepts` is false, the selected result is `none`. Terminal filtering preserves the attached adversary log and the joint hash-query log: a rejected terminal path has still incurred its hash queries. The sampled joint result also includes the final hash cache.

## Security event, assumptions, and quantifier order

`singleSalt_knowledge_soundness` is universally quantified over rounds, Boolean guard schedule, Boolean terminal `accepts`, per-round errors `Fin rounds.length → ENNReal`, the adversary, a knowledge-state family, an extractor family, a set `Z`, relations `Rin` and `Rout`, and a seed function. Its explicit typeclasses include decidable equality for `Statement` and `GlobalSalt`; each `Round` itself carries finite/sampleable challenge and finite message structure. The seed is a **function** `seed z path : Witness → (extractor z).terminalState path.Witness` for every `z` and full path, not an equivalence or inverse. The hypotheses are:

* for every `z ∈ Z`, the round extractor is prover preserving and locally bounded by the schedule that samples each round challenge uniformly with its supplied round error;
* for every `z` and input-state witness, `(state z).holds witness ↔ Rin z witness`;
* for every `z`, path, and `Witness`, `accepts z path = true → Rout z path witness →` the seeded terminal-state witness satisfies terminal `holds`.

The third assumption is one-way and applies only to paths accepted by `accepts`. No theorem hypothesis states that terminal `holds` implies `Rout`, or that the seed can recover every terminal witness. The extractor is supplied to the theorem, not selected existentially by it, and the theorem does not give the extractor the adversary's private random tape. The extractor operates on the completed path and seeded terminal witness through its family of witness maps; its local boundedness and preservation are hypotheses.

The probability samples `randomOracleLoggedRun (singleSaltAcceptedExecution ...) ∅`. It tests only `joint.1.1.1`, the optional selected triple, with `badStoppedRelation`. On `none` the event is false. On `some (z,path,witness)`, it is exactly `z ∈ Z ∧ Rout z path witness ∧ ¬ Rin z ((extractor z).extractWitness path (seed z path witness))`. Since the selected triple survived `accepts`, the probability is of an accepted completed path with a good output relation but a failing extracted input relation. It is an unconditional probability; acceptance is encoded by the optional result rather than used as a conditioning denominator. `badRelation_acceptSingleSaltResult` proves that filtering by `accepts` is equivalent to adding `accepts z path = true` to the output predicate of the unfiltered stopped event.

The theorem bounds this probability by `expectedFreshQueryCharge` of the **accepted execution**, weighted by `keyError errors`. This is the expectation of a sum over distinct hash keys in the entire joint hash log, each weighted by the error of that key's round. Repeated queries to one key contribute once. `singleSaltAcceptedExecution_expectedCharge` proves terminal filtering does not change that charge. There is no explicit adversary query cap in this theorem.

`expectedSingleSaltAdversaryKeys` counts, in expectation over the adversary's own logged run from empty cache, the distinct hash keys it queried; uniform queries are excluded. `expectedSingleSaltVerifierCost` is the expected *list sum* of per-round errors on the suffix of the joint hash log after removing the number of hash entries in the attached adversary log. The stopped completion makes at most one hash query per reached round, and its cost is paid even when terminal acceptance later rejects. `singleSalt_query_cost` proves two inequalities: `expectedFreshQueryCharge(accepted execution) ≤ (sup errors) × expectedSingleSaltAdversaryKeys + expectedSingleSaltVerifierCost`, and `expectedSingleSaltVerifierCost ≤ ∑ j, errors j`. Prefix stopping can reduce the latter actual-round cost; terminal filtering does not. The supremum and sums are in `ENNReal`, with no finiteness or `< 1` premise on errors.

For `singleSalt_knowledge_soundness_queryBound`, the added `Q : ℕ` hypothesis says that **every supported result** of `randomOracleLoggedRun adversary.withQueryLog ∅` has at most `Q` distinct hash keys in its hash log. It does not bound uniform queries, duplicate hash-query entries, or the verifier's queries. The conclusion is `Pr[the same accepted bad event] ≤ Q × sup errors + ∑ j, errors j`. `singleSalt_uniform_query_cost`, separately, bounds the expected charge for constant round error `ε` by `(Q + rounds.length) × ε`; it is a charge statement, while the preceding theorem is a probability statement. The cost cap is an assumption, not derived from the adversary's type.

## Sumcheck specialization

`Sumcheck.Interaction.Restoration.FiatShamir` fixes a finite field `F` with `[Field F] [Fintype F] [DecidableEq F] [SampleableType F]`, natural numbers `n` and `deg`, an injection `D : Fin m ↪ F`, a source oracle shape `A`, and input-indexed `stmt`, polynomial statement `p`, `originalOracle`, and deterministic implementation `impl`. `fieldError F deg` is `(deg : ENNReal) / Fintype.card F`, and `(rounds F deg n).length = n`. `Input` and `Salt` are arbitrary types; the soundness theorems additionally require decidable equality for each. Their adversary outputs a `Unit` witness and chooses a `SaltedProof Salt (rounds F deg n)`.

The guard schedule `sumcheckGuards` checks at each round that the submitted polynomial message's sum over the injected domain `D` equals the current target. On passing, the hash challenge updates the target to that polynomial evaluated at the challenge and appends the challenge to the statement. These are the **prefix checks**: a failure stops before the corresponding hash query. The terminal predicate `singleSaltSumcheckAccepts z path` runs `nativeObservedOutput` on `z.1` and the full path; it returns false if replay yields no output and otherwise decides equality of the final output oracle evaluation at the recorded challenges with the output target. `singleSaltSumcheckAccepts_iff` equates this Boolean with existence of a `nativeObservedOutput = some output` satisfying `Native.outputRelation`. This semantic replay and acceptance predicate ignore the salt, though the hash keys still include it through `z`.

`singleSaltSumcheckExecution` is exactly `singleSaltAcceptedExecution` with those prefix guards and that terminal predicate. Its event `singleSaltSumcheckFalseClaim` is false on `none`; on `some (z,path,())` it is `¬ initialClaimTrue F n deg D stmt p z.1`. Thus an accepted full path is already required by the selected result, while the event asks whether the **unsalted input's initial claim is false**. It does not separately test output acceptance in the event, and no extractor output is returned by the game.

All three Sumcheck bounds assume `sourceLaw`: for **every** input `z`, `(originalOracle z).eval (impl z)` equals the polynomial family's behavior on realizations of `p z`. `initialClaimTrue` is the initial closed relation formed from `stmt z` and that polynomial behavior. The source law is used to show that, on a terminal-accepted path, the certificate's `Unit` terminal witness satisfies terminal `holds`. The client supplies the certificate as the extractor for every `(input,salt)`, uses `Set.univ`, makes `Rin` the initial claim (independent of the unit witness and salt), makes `Rout` identically true, and uses `terminalWitnessEquiv ... path ()` as the seed function. Preservation and constant local boundedness come from the imported certificate theorems. The input-law and event-equivalence steps identify the abstract bad-relation event with `singleSaltSumcheckFalseClaim`.

`singleSaltSumcheck_soundness` bounds the false-claim probability by expected fresh hash-query charge at constant `fieldError F deg`. `singleSaltSumcheck_expected_round_bound` bounds it by `fieldError F deg × expectedSingleSaltAdversaryKeys adversary + expectedSingleSaltVerifierCost` for these guards and terminal predicate. With a supportwise cap `Q` on distinct adversary hash keys, `singleSaltSumcheck_query_bound` concludes `Pr[false claim after accepted execution] ≤ (Q + n) × fieldError F deg`. No condition `deg < |F|` appears; the numerical expression may be at least one. No separate game-equivalence hypothesis appears in these statements: the public execution/stopped-completion correspondence and the terminal-acceptance characterization are proved in the imported code. `sourceLaw`, the certificate properties, and the query cap where used are the operative conditions.
