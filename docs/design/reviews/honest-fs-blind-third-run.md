## Mathematical objects and actual experiments

A `Round` packages message and challenge types, an oracle interface, decidable equality/finite message instances, and finite/nonempty/sampleable challenge instances. The `publicProtocol` used for `HonestProver` has only a public prover-sent message followed by a public verifier-sent challenge each round. It does not insert the `Round.interface` oracle node present in the separate `StateRestoration.protocol`. `PublicMessages` is the tuple of prover messages, with no salts or challenges. The execution path records messages and challenges.

`HonestProver rounds` is an arbitrary `Prover.Strategy` on that public protocol with ambient `unifSpec` and terminal output `Unit`. It can use its permitted uniform oracle through its strategy computations; it is not given the Fiat–Shamir/hash oracle by this type. The fixed `statement` and `witness` are not formal inputs to the strategy type. There is no premise that the witness is valid, the prover follows any canonical algorithm, or the verifier accepts. A caller can of course choose the strategy parameter as a function of other data before applying a theorem.

A `GuardSchedule Input PUnit rounds` consists, each round, of a Boolean guard on the fixed input, current message, and unit salt, plus a continuation schedule depending on the current message, unit salt, and challenge. In `honestInteractiveRun`, the prover selects a message, the guard runs **before** sampling a challenge, and a false guard produces `none`. On a true guard, the challenge comes from the round's `$ᵗ` type sampler, the prover continues after seeing it, and success produces `some (public messages, execution path)`. With zero rounds the run produces the unit messages and unit path. Any later guard failure also yields `none` for the whole run.

`honestCompiledRun` uses the same prover but obtains each challenge by a query to `oracleSpec Input PUnit allRounds`, mapped by `embed`. With identity embedding, the key for the current round includes the fixed input (in the application, `(statement, globalSalt)`), current message, and unit salt; later keys are nested under preceding messages. The query response is cast to the round challenge type. `honestSingleSaltAdversary` first samples one `GlobalSalt` via `$ᵗ`, runs that compiled protocol at `(statement, salt)` with identity embedding, and returns either `none` or `some (statement, (salt, publicMessages), witness)`; it discards the run's path at this stage. It selects no different statement, salt, or witness after running. `SingleSaltAdversary` itself is a broader computation type allowing uniform and hash queries, but the constructed adversary follows this definition.

`honestInteractiveAccepted` samples a global salt, runs the direct interactive protocol with fixed statement and witness, maps a successful run to `((statement, salt), path, witness)`, and filters that optional output by the arbitrary Boolean `accepts (statement, salt) path`. Hence it returns `none` on a failed guard or a false acceptance predicate. `honestSingleSaltAccepted` instead invokes `singleSaltAcceptedExecution` on the constructed adversary. The latter logs the adversary's queries, replays its selected public messages through `singleSaltVerify`, and filters by `accepts`. `singleSaltVerify` runs `publicStoppedVerify` and filters its optional path. The public verifier checks each guard before making that round's hash query; a failed guard stops with `none`. Replay hash queries are forwarded to the same hash oracle and can use values cached by the adversary.

`randomOracleLoggedRun program ∅` runs with an initially empty hash cache, leaves uniform oracle queries as probabilistic queries, implements hash queries by a caching random oracle, and returns `((programOutput, hashQueryLog), finalHashCache)`. Thus `result.1.1.1` in the final accepted theorems is the **optional accepted selection**: it discards the adversary log, the hash-query log, and the final cache. The direct side is a fresh probabilistic run, not a pathwise coupling with a particular cache or log.

## Exported assertions

The central general lemma `honestCompiledRun_eq_interactive` quantifies over any `Input` with `DecidableEq`, any rounds, guard schedule, input and `HonestProver`, plus any key embedding into an `allRounds` oracle. It requires: the embedding preserves challenge types; the embedding is injective; its transported challenge sampler agrees with the local `$ᵗ` sampler at **every** key (`HonestSamplePreserving`); and every embedded key is absent from the initial cache (`HonestCacheFresh`). Under those premises, the distribution of the compiled run's output after ROM simulation and **cache erasure** (`run'`) equals the direct interactive run's distribution. No equality of caches, logs, or individual random choices is asserted. The identity embedding with empty cache is shown to satisfy the extra conditions, giving `honestCompiledRun_empty_eq_interactive` after projecting the logged run to its output.

The adversary projection lemmas `honestSingleSaltAdversary_run'_eq_interactive` and `_logged_eq_interactive` quantify over arbitrary rounds, guards, fixed statement and witness, and arbitrary honest prover, with decidable equality for statement and global salt and a `SampleableType GlobalSalt`. They say the compiled adversary's output distribution, after discarding cache (and logs in the logged version), is the distribution obtained by first sampling salt, then performing the direct interactive run, and retaining only `(statement, (salt, messages), witness)` on success.

`HonestCachedPath` says recursively that each public message equals the corresponding execution-path message, each guard passes, and the final cache contains the path challenge at its embedded key (cast back to the embedded response type). It is `True` at zero rounds. `honestCompiledRun_cached` proves this predicate for **supported runs whose output is `some (messages, path)`**. `honestSingleSaltVerify_replay` and `_rom` then state that verifying such a cached path returns precisely `some path` if `accepts z path` is true, otherwise `none`, without changing the cache. These facts support the accepted-output equivalence; they make no claim about an aborted run's cache.

`honestCompiledVerify_eq_interactive` states, for a fixed salt, equality between the compiled-then-replayed verifier output after ROM simulation with empty cache and the direct run mapped through `honestAcceptedResult`. `honestSingleSaltVerifiedProgram_eq_interactive` adds sampling of the global salt and equates the resulting output computation to `honestInteractiveAccepted`. `honestSingleSaltAccepted_erase_log` identifies the accepted execution's first component with that verified program at the *oracle computation* level after removing its adversary log. The following `run'` and logged versions equate their corresponding **projected output distributions** to the direct accepted computation.

The strongest final assertion, `honestSingleSaltAccepted_event_eq_interactive`, is universally quantified over all `Statement`, `GlobalSalt`, and `Witness` types satisfying `DecidableEq Statement`, `DecidableEq GlobalSalt`, and `SampleableType GlobalSalt`; all round lists, guard schedules, acceptance predicates, fixed statements and witnesses, honest provers; and **every proposition-valued event on the optional accepted output**. It equates the probability of that event on `result.1.1.1` from an empty-cache logged ROM run of `honestSingleSaltAccepted` with the probability of the same event on `honestInteractiveAccepted`. This is an equality of the projected optional-output laws, including the `none` outcome.

`honestSingleSaltAccepted_completeness` instantiates that result with the event `selected.isSome = true`. Its left side is the probability that the logged ROM execution's projected accepted output is present; its right side is the probability that the direct interactive run with a sampled global salt passes every guard and the Boolean `accepts` predicate. It asserts exact equality, with no lower bound or claim that either probability is positive or one.
