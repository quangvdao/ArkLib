## Literal mathematical content

`Round` carries a finite, nonempty challenge type with a sampler. For a finite list `rounds`, `protocol rounds` alternates an oracle message and a public receiver challenge per round. A restoration key contains the selected input, message, salt, and strict prior message/salt chain, but no prior challenge response. `oracleSpec` has one response type, the relevant round's challenge type, for each key. `complete rounds z messages` makes one restoration query per round, forwards later keys with the previous message/salt, and builds the path from those responses. Empty `rounds` has no key and no completion query.

`RandomizedRestorationAdversary Input Salt W rounds` is a total `OracleComp` over the sum of private uniform sampling and the restoration oracle, returning either `none` or `(z, messages, witness)`. This type does not itself impose a query count. The uniform summand is forwarded to probability sampling and is not entered in the restoration cache or hash-query log. The restoration summand is interpreted by one lazy cached random oracle: repeated keys receive the cached answer, and all accesses appear in the ordered log. An adversary can adapt each next choice to its private samples and prior restoration responses. If it returns `none`, the verifier returns `none`, but all earlier restoration queries remain in the observed log and final cache. If it selects a transcript, completion uses the same cache and adds its round keys. The source adversary log is retained separately before completion. Native replay and terminal observation are functions of this completed path; the replay equality states that the replay adds no ambient restoration query. The closed native game maps any open claim through the completed path's own closing implementation; rejection is `none` inside a selected game result.

`freshKeysOfLog` converts the ordered restoration log to a finite set of distinct keys, and `freshQueryCharge error` sums `error key` over that set. It counts a queried key once, including one originally queried by the adversary and later queried by completion. `expectedFreshQueryCharge` is the `ENNReal` integral of this charge over the full logged cached run, including `none` selections. `expectedAdversaryFreshKeys` is the expectation of the cardinality of the distinct restoration keys at the *actual cached adversary-phase boundary* (`randomOracleLoggedRun adversary.withQueryLog ∅`). `expectedJointAdversaryKeys` reads the retained source-phase log in the completed run, and a theorem equates these expectations. Neither expectation conditions on success. Errors are arbitrary `ENNReal` values indexed by protocol round; there is no hypothesis here that they are finite or below one. `keyError` assigns a key its round's error. The second charge inequality is `E[joint distinct-key charge] ≤ (max_j errors_j) · E[distinct adversary keys] + Σ_j errors_j`, with an empty-round maximum/sum of zero. Each completion round contributes at most its round error, irrespective of a cache hit; overlap can only lower actual charge.

`RoundExtractor` is supplied for every input `z`, with a total backward witness map at every typed path node. It is not synthesized by these theorems. `IsProverPreserving` requires its maps at prover/oracle nodes to preserve knowledge for all moves/messages. `IsLocallyBounded` uses fresh uniform receiver challenges and requires the local bad-challenge probability bound at every authored prefix, including prefixes unreachable in an actual execution. Both hypotheses are required only for `z ∈ Z`; outside `Z`, the theorem makes no failure claim. The local bad challenge has an existential later witness *inside* the challenge event. `terminalWitness z path` is a supplied equivalence from adversary witness type `W` to the extractor's terminal witness carrier, and `extractInputWitness` applies that equivalence and the named backward maps on the same completed path.

`badObservedRelation` is false on an outer `none`. On `some (z,path,output,witness)`, it is exactly `z ∈ Z ∧ Rout z path output witness ∧ ¬ Rin z (extractInputWitness ... z path witness)`. In the scalar specialization, `output` is the actual `Out z path.toBranchPath` from `terminalObservation`. Its `inputLaw` equates the root state's `holds` predicate and `Rin` for all `z,witness`. Its `outputLaw` equates the terminal state's `holds` predicate and `Rout` of that observation for all `z,path,witness`. In the closed specialization, `output` is `Option (ClosedClaim ...)`; `Rout` is applied only if there exists `claim` with `output = some claim`. The closed output law equates terminal `holds` with existence of such an accepted claim satisfying `Rout`, for all `z,path,witness`. Thus rejected closed outputs and failed selections cannot be bad events, though their queries contribute to the expectation.

`randomizedVerificationGame_expected_knowledge_soundness` and `randomizedClosedVerificationGame_expected_knowledge_soundness` assert a pair of inequalities. First, the probability of that exact relation failure in the actual native verifier distribution, initialized with empty restoration cache, is at most the expected distinct-key charge of the instrumented observed game. Second, this charge is at most the above maximum-error times expected actual adversary-phase distinct key count plus sum of round errors. The output marginal/event theorems identify the actual game distribution with the instrumented run after forgetting both logs and cache, so the first inequality is for the returned output from that run. The scalar and closed variants differ in their output types and laws, but use the same adversary/completion distribution.

Each `*_queryBound_knowledge_soundness` corollary adds `Q : ℕ` and a support-wise cap: every supported result of `randomOracleLoggedRun adversary.withQueryLog ∅` has at most `Q` distinct restoration keys in its hash log. This quantifies over successful and failed selections. It concludes failure probability at most `Q · max_j errors_j + Σ_j errors_j`. A separate theorem equates this support cap to event probability one for the adversary-phase run. `Q` does not bound uniform sample operations, repeated restoration calls, or completion calls. No claim about extraction runtime or computational efficiency is present.

The first inequality imports VCVio's expected fresh-query theorem: for every fixed complete answer table, bad output of the *same* logged execution must expose a bad key in that log, and each key's bad predicate has the local resampling bound under any background table. The ArkLib proof supplies those via its fixed-table path reconstruction and all-prefix local assumptions. VCVio's theorem allows arbitrary hash-key domains through finite possible-key restriction; the imported result is at the pinned dependency revision above.

Potential vacuity/boundary observations from the statements: `Z = ∅`, no selected transcript, absent `Rout` claims, or no valid terminal witness make the bad event false. These are parameter choices, not inconsistencies. The endpoint equivalences can be restrictive for a concrete verifier and must be discharged by its consumer. The error expression can be loose or infinite; the theorem does not assert a nontrivial numeric bound for every supplied error vector. Empty rounds have zero key charge and no bad challenge under the preserving premise. I did not find a statement that conditions charge on successful selection.
