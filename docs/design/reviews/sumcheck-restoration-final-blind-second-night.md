## Mathematical objects and game

The field `F` has `[Field F] [Fintype F] [DecidableEq F] [SampleableType F]`; the `SampleableType` law says `$ᵗ F` is uniform over `F`. The number of rounds `k` and polynomial degree parameter `deg` are arbitrary natural numbers. The domain is an embedding `D : Fin m ↪ F`, so its image has `m` distinct elements; no nonempty-domain assumption is stated. Each round's prover message is a univariate polynomial of degree at most `deg`, and its challenge is an element of `F` (`StateRestorationCertificate.lean:30-45`, `SingleRound.lean:32-39`). `p z` is a multivariate polynomial oracle statement with index set `Fin k` and bound `deg` (`Spec/SingleRound.lean:130-146`).

For an initial statement `stmt z = (target, challenges)` at round index zero, `initialClaimTrue z` is `closedRelation` for the realization of `p z` (`StateRestorationSoundness.lean:124-126`). Expanding `closedRelation` (`MultivariateRound.lean:251-255`), its assertion is that the sum of this polynomial's evaluations over every `k`-tuple drawn from the image of `D` equals `target`. At later index `i`, the first `i` coordinates are the recorded challenges and the remaining `k-i` coordinates range over the domain image. At index `k`, the relation is a single evaluation at the full challenge vector equal to the current target (`MultivariateRound.lean:288-291`).

The adversary has type `RandomizedRestorationAdversary Input Salt Unit (rounds F deg k)`, where `Input` and `Salt` are arbitrary types with decidable equality. It is an `OracleComp (unifSpec + oracleSpec Input Salt rounds)` returning `Option (Input × Messages Salt rounds × Unit)` (`StateRestorationRandomized.lean:35-37`); it can make random and keyed hash queries before returning an input, a full sequence of degree-bounded polynomial messages and salts, or `none`. The keyed oracle's response type at each key is that round's challenge type. A key includes the input, round message and salt at the first level, or the preceding message/salt history and a later key (`StateRestoration.lean:57-60,214-220`). `randomizedRestoredExecution` then queries this random oracle at each of the `k` prescribed keys to complete a path; it does so even for a message whose sum check later fails (`StateRestorationRandomized.lean:214-222`, `StateRestoration.lean:230-237`). The main probability uses `romImpl` and an initially empty cache, so it is over the adversary's randomness and the random responses in this completion.

For each result path, `nativeObservedOutput` replays the path's prover polynomials and challenges through `Native.execute` using a deterministic challenge replay and the specified `originalOracle z` / `impl z` (`StateRestorationEvaluation.lean:88-119,146-155`; `StateRestorationSoundness.lean:136-139`). The replay theorem equates this output with `paddedStatement`: at each round, the polynomial's values summed over the domain image must equal the running target; failure returns `none`; success updates the target to the polynomial evaluation at the path challenge and appends that challenge; after `k` rounds it returns the final statement (`StateRestorationEvaluation.lean:27-36,110-121`). The output is a `ClosedClaim` that also carries the evaluation behavior of the supplied original oracle. `Native.outputRelation` tests whether this closed claim's polynomial oracle evaluates at the final challenge tuple to the final target (`Protocol.lean:137-138,339-354`).

`nativeRestorationGame` maps every completed result to `(input, completed path, nativeObservedOutput, Unit)` and leaves `none` as `none` (`StateRestorationSoundness.lean:159-172`). `nativeFalseAccepts` is false on `none`; on `some` it requires both `¬ initialClaimTrue z` and an observed `some claim` satisfying `Native.outputRelation` (`StateRestorationSoundness.lean:176-183`). Thus this is false acceptance of the initial sum statement by the replayed native verifier. The event does not separately test the path's extraction certificate or expose the adversary's query log. The theorem `nativeRestorationGame_falseAccept_event` identifies its probability with the same event on the observed logged random-oracle game (`StateRestorationSoundness.lean:218-230`).

## Exported main probability statements

`nativeRestoration_expected_soundness` (`StateRestorationSoundness.lean:259-279`) universally takes `F`, `k`, `deg`, `D`, arbitrary `Input`, `Salt`, `A : PFunctor`, input-indexed `stmt`, `p`, `originalOracle`, `impl`, and an adversary of the above type. Its substantive additional hypothesis is

`∀ z, (originalOracle z).eval (impl z) = (polynomialFamily F k deg).behaviorOfRealizations (fun _ => p z)`.

This is an extensional equality of the implemented original oracle's behavior with the polynomial statement for **every** input, independent of the adversary's selected input. There is no hypothesis that the initial claim is false; falsity is part of the measured event.

The theorem is a conjunction. First, the probability of `nativeFalseAccepts` for the actual `romImpl` run of `nativeRestorationGame` from empty cache is at most `expectedFreshQueryCharge` of the logged observed game, weighted by `keyError` with constant per-round error `fieldError F deg = (deg : ENNReal) / Fintype.card F`. Second, that charge is at most

`fieldError F deg * expectedAdversaryFreshKeys (rounds F deg k) adversary + (k : ENNReal) * fieldError F deg`.

By transitivity, the false-acceptance probability has the latter bound. `expectedFreshQueryCharge` integrates the sum of the per-key errors over distinct keys in the full random-oracle query log of the observed game, including completion (`VCVio/OracleComp/QueryTracking/RandomOracle/LoggedRun.lean:205-214`). `expectedAdversaryFreshKeys` integrates the cardinality of the distinct keyed-oracle queries in the *adversary phase's* log, before completion (`StateRestorationRandomized.lean:868-877`; VCVio `LoggedRun.lean:31-33`). Uniform per-round errors give `deg / |F|` per key, and completion contributes at most `k` additional keys. The result is an `ENNReal` inequality; if this expression is at least one, it is correspondingly weak, with no separate assumption `deg < |F|`.

`nativeRestoration_queryBound_soundness` (`StateRestorationSoundness.lean:322-343`) has the same parameters, oracle source law, and adversary, plus a natural `Q` and the hypothesis that every supported result of `randomOracleLoggedRun adversary.withQueryLog ∅` has at most `Q` distinct keyed-oracle queries in the adversary log, `freshKeysOfLog phase.1.2`. Under that support-wise bound, the actual false-acceptance probability is at most `((Q + k : ℕ) : ENNReal) * fieldError F deg`, i.e. `(Q+k)deg/|F|` in extended nonnegative reals. This `Q` counts distinct keyed oracle queries (not all uniform/random queries, and not repeat occurrences of the same key); the `k` term covers the prescribed completion queries. No finite total-query bound on the adversary is a theorem hypothesis. `k=0`, `deg=0`, and an empty domain are allowed by the statement. For `k=0` there is no completion key or random challenge; the initial and final relation coincide and the displayed bound is zero when `Q=0` (indeed keyed queries have empty key type).

## Certificate and coupling interfaces behind the theorem

`certificate` assigns unit witness states to the initial and every intermediate claim, accumulating the conjunction of all passed polynomial sum checks; its state predicate is that conjunction and the current `closedRelation` (`StateRestorationCertificate.lean:50-74`). `certificate_preserving` says prover/oracle moves preserve truth of the extracted predecessor state; `certificate_locallyBounded` says each uniformly sampled challenge causes a false-to-true successor transition with probability at most `deg/|F|` (`StateRestorationCertificate.lean:79-139`, `Knowledge.lean:201-211,330-366`). The local polynomial fact invoked for the nontrivial case is `uniform_successor_soundness`: if the current closed relation is false but a prover polynomial passes the current domain-sum check, a uniform challenge makes the successor closed relation true with probability at most `deg/|F|` (`ProtocolSoundness.lean:40-49`). The certificate is an analytical witness, not an extra success condition in the native event.

`terminal_holds_iff` equates the certificate's terminal truth with all checks passing and the padded final statement satisfying `Native.outputRelation` (`StateRestorationEvaluation.lean:56-85`). `terminal_holds_iff_native` additionally uses the `sourceLaw` to replace the polynomial realization by the native replay's closed output (`StateRestorationEvaluation.lean:160-177`). For the full `k` rounds and initial `True`, `terminal_certificate_holds_iff_native` removes the leading `True` (`StateRestorationSoundness.lean:144-155`). This is the exact bridge used by the randomized observed relation theorem; `nativeFalseAccepts_iff_ownerEvent` aligns the concrete false-accept event with its generic bad-observed-relation event (`StateRestorationSoundness.lean:235-254`). The observed game's marginal is proved equal to the native game's result distribution and its event probability (`StateRestorationSoundness.lean:188-230`). The bound is therefore about this exact randomized restored/replayed native game, not merely a fixed-table or logged auxiliary event.

## Limits and unresolved interpretation

- The theorem statements impose no efficiency or termination condition beyond what their `OracleComp` types themselves encode. They also do not themselves give a bound for a differently defined native Fiat–Shamir verifier or a wrapper that accepts a different output relation.
