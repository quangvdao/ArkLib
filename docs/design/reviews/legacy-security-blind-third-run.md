## Fixed-table projection and game equality

`FixedTableCacheCompatible table cache` means *every* cache entry is either absent or exactly the table's value at that key. The empty cache satisfies it, and inserting the table's answer preserves it. It asserts neither equality of query logs nor equality of caches. The specialized `fixedTableLoggedRun_restored_value` applies this with an empty cache to randomized restoration execution, and projects the native `Option (Input × completed path × W)` from the logged joint run.

For every fixed native table `Table Input PUnit rounds`, `legacyFailure_fixedTable_eq_native` equates two `ENNReal` event probabilities: (1) a legacy prover run against the table reindexed by `nativeTableToLegacy`, followed by deterministic transcript derivation and the native legacy result; and (2) the simulated native adversary completed against the same table, tested by `badStoppedRelation`. The equality uses path/transcript correspondence and the event equivalence. `legacyFailure_eager_eq_native` integrates that pointwise equality over `$ᵗ (Table Input PUnit rounds)` and replaces the native value run with the value projection of `fixedTableLoggedRun`. Its explicit instances are `[DecidableEq Input]` and `[SampleableType (Table Input PUnit rounds)]`. The initial cache is empty. Thus the final eager equality includes the verifier/completion hash calls in the logged run while the event inspects only its selected completed path.

Its other data are a state indexed by input, a path extractor indexed by input, a seed `(input, path, W) → terminal-state witness`, a map from extracted initial-state witness to `WitIn`, an observation `(input,path) → Option StmtOut`, and input/output relations.

The hypotheses require: (i) the extractor for **every** input is prover-preserving; (ii) for **every** input it is locally bounded by `roundErrorSchedule rounds errors`; (iii) for every input and initial-state witness, the state's `holds` predicate is equivalent to input-relation membership after `witnessMap`; and (iv) whenever an observed output and `W` satisfy the output relation, the seeded terminal witness satisfies the terminal state's `holds`. The last implication is one-way. The conclusion bounds the actual instantiated `Verifier.StateRestoration.coinKSExperimentProb` by

`(Finset.univ.sup errors) * expectedAdversaryFreshKeys rounds (simulateLegacyProver rounds prover) + ∑ j, errors j`.

## Scope and conditions visible from code

This is a conditional security theorem. The state, extractor, seed, `inputLaw`, and `outputLaw` are parameters/hypotheses, not constructed from an arbitrary protocol. `Round` itself supplies finite, nonempty, sampleable challenge types; the final theorem constructs legacy challenge sampling/compatibility instances. The salt is one global component of the proof and the native restoration key uses `PUnit` salt internally. If `langOut` is empty or observation never accepts, the failure event is empty. If no total seed exists for a proposed state/extractor, the theorem cannot be instantiated. The errors are arbitrary `ENNReal`; `Q * maxError + sumError ≥ 1` gives only a trivial probability estimate. Empty `Statement` can also make the prover's output type empty. None of these cases is excluded by the final statement.
