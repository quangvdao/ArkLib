## Literal public experiment and theorem

`QuerySite config rounds` is a slot `< rounds`, a configuration tag, and a Boolean leaf selector shaped by that tag's Merkle skeleton. A `PublicOpening` pairs a site with a VCVio `BatchOpening` of the matching skeleton. A `QueryPlan` contains an ordered list of sites and an arbitrary Boolean function of the ordered lists of selected opened leaf values. A `BatchOpening` necessarily selects at least one leaf via its proof type. Sites may repeat, and the plan may have zero sites. There is no uniqueness, coverage, or plan length requirement beyond equality with the submitted openings list.

For `rounds = r`, the sender issues exactly `r` public `(tag, root)` commitments, sequentially, then one public list of openings. Its committer may query the random oracle at each commitment; its opening program receives both the private committer state and the full `ExtractorState`, including cumulative query logs and all checkpoints. The verifier gets the public roots/openings, not the private state or query logs. The native verifier evaluates every batch opening against the public root at its claimed slot (falling back to the supplied `fallback` value if absent), then accepts precisely when: the roots list has length `r`; the submitted opening count equals plan site count; pairwise slot, tag, and both selectors match the plan; each plan slot's public tag matches; all Merkle batch proofs verify; and `plan.decide` applied to the selected leaf values is true. Verification is executed after all commitments/openings. The roots-length and slot validation make the root fallback unreachable on accepting transcripts. `verifyOpeningClaims` still evaluates the opening proofs before the Boolean plan check.

The concrete game runs the typed two-party `executeStrategies`, using the above prover/verifier, under one empty-cache `withCacheOverlay`; this is a single shared oracle cache across all phases. `nativeGame_eq_source` and the coupled equalities identify its projected view with the sequential VCVio committer execution and the same opening program. The coupled transcript preserves public roots/openings and private checkpoint state, terminal opening-phase query suffix, and evaluated opening attempts. The owner projection drops public roots/openings and maps to VCVio's multi-checkpoint extractability experiment with claims assembled from the same execution. Its checkpoint logs are attached to each public opening according to its slot. On a plan-valid transcript, the slot/tag checks ensure that attachment refers to a recorded checkpoint.

The ideal acceptance bit uses the same coupled execution of adversary commitments/openings and verifier queries, but tests plan validity and applies `plan.decide` to *extracted* selected leaf values at the designated checkpoints. Extraction reconstructs a full option-valued tree from the checkpoint's cumulative pre-opening log and committed root, then replaces every missing cell with the supplied fallback value; it selects leaves using the plan selector. The ideal bit does **not** require the real batch proofs to be accepted, and it does not use the terminal opening-phase log to populate the ideal answers. It does require the submitted opening list to match the plan and public roots. The ideal predicate receives only the extracted values, though the game sampling still runs the same adversary and verifier query programs.

For every model, configuration, round count, plan, fallback, adversary, and under the stated decidable equality and lawful probability semantics instances, `prob_realAcceptance_le_ideal_add_checkpointBad` asserts

`Pr[real acceptance] ≤ Pr[ideal acceptance] + Pr[VCVio owner any-checkpoint extraction disagreement]`.

The bad event is a union: an accepted submitted opening differs from the checkpoint-extracted opening; two recorded checkpoints with the same tag and root have differing extracted trees; or a checkpoint's extracted tree changes when the opening-phase query suffix is appended. The pointwise proof uses only the first disjunct: if all submitted proofs accepted and plan-valid, no accepted-opening disagreement implies equality of selected opened and extracted values. The other disjuncts are inherited from the stronger VCVio owner event and affect the error bound.

The main numeric theorem, `realAcceptance_rom_bound_of_prefixQueryBound` (lines 1193–1225), asserts

`Pr[real acceptance] ≤ Pr[ideal acceptance] + E(N,K,V,Q)/|Y|`,

where all probabilities and arithmetic are `ENNReal` and `E(N,K,V,Q) = sup_{0≤m≤Q} [choose(m,2) + min(N, 2m+K)·(Q+V)]` as a natural number cast to `ENNReal`. Here `Q=queryBound`, `N=nodeBudget`, `K=checkpointCount`, `V=verifierOverhead`. The denominator is `Nat.card Y`, requiring finite inhabited `Y` (hence positive cardinality). The oracle is an `IsUniformMeasureSpec` on `Query →ₒ Y`, with `MeasurableSpace Y` and `DiscreteMeasurableSpace Y`; there is no cryptographic hash assumption beyond this random-oracle model. The `NodeQueryModel` supplies a query view `(address,input pair)` and a query constructor with matching address/input equations; the Merkle verification uses the constructed queries.

Its hypotheses require the VCVio owner adversary built from this adversary to have an `IsTotalQueryBound` of `Q` on the committer-plus-opening *prefixProgram* (not the verifier); all possible opening claim lists from any private state/extractor state to have aggregate batch-proof query count at most `V`; every tag's skeleton node budget at most `perCheckpoint`; `r·perCheckpoint ≤ N`; and `r ≤ K`. The owner prefix program discards the claims after executing the opening program. These are substantive external assumptions; the source does not derive them from a particular adversary/plan. `HasVerifierQueryBound` is quantified over arbitrary private states and extractor states, not only reachable ones. No time/PPT bound is stated.

`realAcceptance_le_eta_add_romError` (lines 1229–1256) adds an externally supplied hypothesis `Pr[ideal acceptance] ≤ η` and substitutes it in the right side. It does not establish that ideal probability bound. `η` is any `ENNReal`; if chosen large, this final bound is correspondingly uninformative. The `E/|Y|` term may likewise exceed 1; no nonvacuous parameter regime is assumed. At `r=0`, the plan has no sites and the result may accept based on `plan.decide []` without Merkle proofs; this is within the literal statement.

## Information, timing, and extraction caveats

The query plan is supplied as a fixed public parameter before the experiment, not chosen by the verifier adaptively from observed roots. Its sites carry slots/tags/selectors but no private witness. The adversary may choose the public opening list after seeing its own state and checkpoint logs, and its opening program may make further oracle queries. The verifier's proof checks can also query the oracle, sharing the cache. The private state/logs are retained in the coupled projection for the analysis; no public theorem asserts the verifier learns those logs. Extracted cells are `Option Y` before fallback filling. The extracted ideal leaves are anchored to the *checkpoint* cumulative log, not to the terminal log, which is why terminal evolution is included in the owner bad event even though the pointwise implication needs only opening disagreement.

Potential vacuity is local to chosen parameters and plan: an always-false plan makes both acceptance probabilities zero; an always-true plan with no sites can make both probabilities high. The theorem does not itself claim low real acceptance without `hideal` and a small numeric error. No specific opening count bound, efficient extractor, or reduction runtime is packaged by this module. The reconstruction is deterministic from query logs and roots; the only probabilistic lifting is via the coupled game and VCVio's upstream random-oracle bound.

### Finding P2 — verification-free ideal marginal is missing

**Evidence.** `idealAcceptanceExperiment` at lines 1093–1102 is only `idealAccept` mapped over `coupledExperiment`. `coupledExperiment` calls `coupledInner` (566–581), which executes `verifyOpeningClaims` on every adversarial opening at line 573 before producing the transcript. `prob_idealAcceptance_eq_coupled` (1122–1134) is a definitional `prEvent_map` equality to this same coupled experiment. There is no separate ideal runner that stops after the commitment/opening phase and computes extracted answers without running honest proof verification, and no theorem equating the two Boolean marginals. Repository search found no such target-specific theorem or consumer. The exported η corollary therefore accepts a bound on the *coupled* ideal experiment, whereas a natural bound on an ideal verifier that reads only checkpoint-extracted selected leaves cannot be plugged in directly.

**Contract/consequence.** The contract calls for `IdealVerify(extractA)` to read the prescribed extracted positions and apply the decision, with actual-game marginal equations. The ideal *predicate* in `idealAccept` does do that, but the exported ideal *experiment* additionally samples verifier RO queries. Those queries can change the final cache/log; a full execution equality to a verification-free runner would be false. Under the main theorem's uniform measure-spec assumptions the extra verification is lossless and the ideal Boolean marginal should be equal: VCVio's `OracleComp.prEvent_true_eq_one` (pinned `OracleComp/EvalDist/Measure.lean`, line 333) applies to every finite `OracleComp` verification continuation. This equality is mathematically plausible but is not established in ArkLib's public API. Its absence blocks applying the η transfer to the clean ideal verifier without a fresh consumer proof. This is a material bridge gap, not a counterexample to the proved inequality.

**Smallest repair.** Define a named `idealCoreExperiment` that uses the same `runFromEmpty` and terminal opening phase in one empty-cache overlay, then computes `idealAccept` from checkpoint-time extraction before any `verifyOpeningClaims`; preserve a suitable prefix transcript to identify roots/openings/state. Prove a Bool probability marginal equality between it and `idealAcceptanceExperiment` under `IsUniformMeasureSpec` (or an explicit lossless verifier premise), using losslessness of `verifyOpeningClaims`. Do not assert full cache/log equality, since verifier queries can add entries. Offer the η corollary against that clean ideal marginal or a bridge theorem consumers can use. The pointwise real-vs-coupled-ideal proof and exact ROM numerator can stay as they are.
