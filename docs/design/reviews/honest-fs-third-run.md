**Verdict: REQUEST CHANGES for full S1 contract; no mathematical flaw found in the stated restricted theorem.** The theorem faithfully proves accepted-output equality for a salt-oblivious `HonestProver`, but the exported honest prover type cannot receive the freshly sampled public salt before choosing its first message. This omits a natural class of honest single-salt strategies. A minimal repair is to accept `prover : GlobalSalt → HonestProver rounds` (or a pure function of full public input) in both the interactive source and compiled adversary, apply it after the salt draw, and discharge the fixed-salt replay/equality pointwise. Keep the function itself fixed before sampling, so the salt remains independent of private draws. If S1 intentionally means a prover whose *messages* are salt-oblivious, document that scope explicitly; under that narrower scope the current proof is acceptable.

Evidence: `HonestProver rounds` at lines 27–30 depends only on `rounds`. `honestSingleSaltAdversary` at 78–85 and `honestInteractiveAccepted` at 89–98 each sample `salt` and then pass the unchanged `prover` to their run. `honestSingleSaltVerifiedProgram` at 622–634 repeats this. Guards and hash keys do depend on `(statement,salt)`. For a Boolean message/salt round with guard `message = salt`, an honest prover told the public salt can pass surely; no fixed salt-oblivious first-message strategy can realize that behavior with an independently sampled fair salt. The accepted-output equality compares two programs with this same restriction, so it does not close the omitted case.

Within the stated API, the distribution proof is substantive. `honestInteractiveRun` (35–47) preserves an adaptive private continuation after each challenge, with `unifSpec` as the only ambient prover effect; it stops before challenge sampling on a failed guard. `honestCompiledRun` (52–73) lifts the same private computations and queries full-prefix hash keys only after the guard. The general equality at 194–261 explicitly requires injective embedding, sampler preservation and fresh suffix keys; the identity/empty-cache application discharges these assumptions rather than exporting them in the final theorem. `HonestCachedPath` and `honestCompiledRun_cached` (365–547) establish that every successful compiled path's verifier challenges are cached, while `honestCachedPath_replay` (409–450) and `honestSingleSaltVerify_replay_rom` (581–599) prove the native verifier returns that path and leaves the cache unchanged. Hence verification does not resample a completed honest path.

The final chain reaches the real accepted wrapper: `honestCompiledVerify` (604–617) invokes `singleSaltVerify`, rather than filtering the compiled path itself; `honestSingleSaltAccepted_erase_log` (722–770) relates it to `singleSaltAcceptedExecution`. The logged output projection (793–814) and native-measure all-event equality (818–835) are exact for the optional accepted result. The completeness theorem (839–852) is the success-event instance. This exact probability transfer needs no losslessness assumption; it remains valid for aborting or subprobabilistic private strategies. It does not prove any positive lower bound, which must be supplied by an honest interactive source completeness hypothesis/application. The statement also deliberately projects away logs and cache; no equality of those is claimed.

A secondary fidelity boundary is that `honestInteractiveRun` is a new direct interpreter, not a proved correspondence to a pre-existing `executeStrategies` interactive experiment or the legacy `Prover.fiatShamir` construction (legacy Basic still has its completeness theorem deferred). Its structural schedule matches the public message/challenge protocol, so this is not a soundness defect in the displayed law, but callers should not describe the theorem as transporting an arbitrary legacy reduction's completeness without an adapter.

The independent blind read-back accurately identified the actual wrapper, option-valued event law, cached replay, lack of losslessness/threshold, and absence of log/cache equality. Its only material omission for S1 fidelity is the public-salt visibility restriction above.

Because the current `HonestProver` targets the *unguarded* `publicProtocol rounds` (`PublicMessage.lean:29`) whereas the guarded tree terminates on rejection, a guard-aware adapter/truncation of its continuation is needed before applying `executeStrategies`. The result's path is the guarded tree's path, so decode successful full paths to `(PublicMessages rounds × (protocol rounds).tree.ExecutionPath)` and map failed guards to `none`. No theorem in `HonestSingleSalt.lean` presently identifies that actual executor with `honestInteractiveRun`.
