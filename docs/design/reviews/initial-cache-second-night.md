- A `SampleableType T` supplies a sampling computation whose evaluation is the uniform measure on all of `T`; it implies `T` is finite and nonempty (`SampleableType/Basic.lean:51-86`). `Pr{let x ← m}[P x]` is the evaluation measure of the computation returning proposition `P x` applied to `{True}` (`ProbabilityNotation.lean:65-67`). The bound is measure-valued `ENNReal`; it is not a statement about implementation time or an asymptotic negligible function.
- The cache maps each key to an optional answer. `completeTable cache g` takes cached answers where present and `g` elsewhere (`DependentTable.lean:28-29`). A random-oracle query returns a cached answer if present, otherwise samples a uniform answer and adds it to cache (`Basic.lean:24-47`; `CachingOracle.lean:39-44`). `randomOracleLoggedRun` logs each oracle query and returns the result, log, and final cache; `fixedTableLoggedRun` uses the same cache and logging but supplies uncached answers from a fixed dependent table (`LoggedRun.lean:86-101`; `LoggingOracle/Core.lean:81-89`). Interleaved `unifSpec` draws are passed through and are not counted as oracle keys.
- `freshKeysOfLog` is the *set of distinct key names appearing anywhere in the log*, regardless of whether a key was already cached (`LoggedRun.lean:31-45`). `newQueryKeys cache log` filters that set to keys with `cache t = none` in the **initial** cache (`InitialCacheExpectedQuery.lean:29-35`). Thus repeated queries to a newly sampled key incur one charge, while queries to initially cached keys incur none. `newQueryCharge` sums `error t` over that finite set; `expectedNewQueryCharge` is its Lebesgue expectation over the random-oracle logged run started from the specified cache (`InitialCacheExpectedQuery.lean:45-56`). The charge may exceed one or be infinite.

## Exact theorem readback

The principal public result `prEvent_randomOracle_le_expectedNewQueryCharge` (`InitialCacheExpectedQuery.lean:232-242`) has arbitrary types `D, α`, dependent answer family `R : D → Type`, `DecidableEq D`, and a `SampleableType (R d)` for every key; it does **not** require finite `D` or a sampleable full table. It quantifies over an oracle computation `oa : OracleComp (unifSpec + ofFn R) α`, any initial cache, any event predicate `event : α → Prop`, any full-table bad predicate `bad : D → ((d : D) → R d) → Prop`, and weights `error : D → ENNReal`. Its two substantive premises are:

1. For **every** full table `g` and every outcome `z` in the support of `fixedTableLoggedRun oa g cache`, if `event z.1.1` holds, there is a key `t` in `newQueryKeys cache z.1.2` for which `bad t (completeTable cache g)` holds (`InitialCacheExpectedQuery.lean:237-238`). This is a deterministic, support-level witness requirement. It requires the bad witness to be a query absent from the initial cache, not merely any queried or bad cached key. The event is on the computation's output only; the trace is used to witness it.
2. For **every** key `t` and full table `g`, whenever `cache t = none`, an independent uniform answer `u : R t` inserted at `t` yields `bad t (completeTable cache (Function.update g t u))` with probability at most `error t` (`InitialCacheExpectedQuery.lean:239-240`). There is no required bound for initially cached keys, since those keys are never charged. This premise must hold uniformly over all background values at uncached cells, while cached contents remain fixed by the supplied `cache`; an application does not quantify over other initial caches.

The conclusion is that the probability of `event` in the *adaptive random-oracle logged run begun at that cache* is at most the expected sum of the weights for the distinct logged keys absent from that initial cache (`InitialCacheExpectedQuery.lean:241-242`). The weights are deterministic by key, while the set of charged keys depends on the run and its interleaved randomness.

The finite-domain engine `prEvent_interleavedInitialCacheBad_le_expectedCharge` (`InitialCacheExpectedQuery.lean:149-160`) has the same witness, per-key hypothesis, and conclusion, but additionally requires `Finite D` and `SampleableType ((d : D) → R d)`. It samples a full table and overlays the initial cache. The public theorem removes those requirements by restricting `oa` to its finite set of syntactically possible random-oracle keys (`FiniteSupport.lean:35-69`; `InitialCacheExpectedQuery.lean:243-285`), proves log/charge preservation under restriction (`InitialCacheExpectedQuery.lean:74-113`), applies the finite-domain engine on the subtype, then transports the result. The finite set is possible keys across all branches, not a bound on actual query count.

The key-specific lemma `prEvent_interleavedKey_bad_le_of_initialCache` (`ExpectedFreshQuery.lean:277-390`) bounds the joint event “key `t` occurs in the log and the completed table is bad at `t`” by the probability of logging `t` times `error t`, assuming `cache t = none`. Its factorization depends on the probability of *ever querying `t`* being invariant when the fixed table's answer at `t` is replaced (`ExpectedFreshQuery.lean:161-237,319-332`), even with interleaved private uniform draws. The finite engine applies a union bound to these key-specific events and integrates the sum of charges (`ExpectedFreshQuery.lean:475-502`; `InitialCacheExpectedQuery.lean:172-223`). The eager-table/logged-run distribution equality overlays the initial cache and is proved by induction with a uniform-table resampling lemma (`ExpectedFreshQuery.lean:28-147`).

The empty-cache identities `newQueryKeys_empty_cache`, `newQueryCharge_empty_cache`, and `expectedNewQueryCharge_empty_cache` (`InitialCacheExpectedQuery.lean:38-69`) make the new charge equal the older distinct-logged-key charge. `prEvent_randomOracle_le_expectedFreshQueryCharge_via_initialCache` (`InitialCacheExpectedQuery.lean:289-311`) is an empty-cache corollary of the public theorem, with the corresponding empty-cache witness and resampling premises. The preexisting finite-domain `prEvent_interleavedFreshBad_le_expectedCharge` remains as a separate declaration in `ExpectedFreshQuery.lean:527-585`; its key-specific helper is now an empty-cache specialization of the generalized helper (`ExpectedFreshQuery.lean:394-404`).

## Assumptions, boundary cases, and trust readback

- The support-level trace implication is necessary and potentially strong: if the program can trigger `event` without querying a key absent from the initial cache, no such premise can hold for that outcome. In particular, a full initial cache makes `newQueryKeys` empty and forces any admissible `event` to have zero probability. This is not a claim that arbitrary events are small. A `bad` predicate that is always true can satisfy the premises with a loose weight such as `error t = 1`, yielding a correspondingly loose bound; `hbad` is the actual source of numerical smallness.
- The theorem does not assert independence of the adaptive queried set from all table cells; it needs only the query-*membership* invariance for each key under resampling that key. The proof's support witness and per-key probability premise have compatible quantifier order: `event` is bounded after `oa, cache, bad, error` and both universal hypotheses are supplied.
- An initially cached bad value is carried into the completed table and can influence `event` and `bad`, but it is neither resampled nor charged. A fresh key must still witness any event. Uniform cells are finite and nonempty via `SampleableType`; `D` may be empty/infinite. Empty/no-new-query runs have zero charge and require the support implication to rule out a winning event.
- The change introduces no `sorry`, `admit`, `unsafe`, explicit axiom, or `native_decide` token in either changed proof module (source scan). It uses classical choice for finite subtype enumeration, table extension outside possible keys, and discrete measure instances; these are mathematical/proof conveniences, not runtime code guarantees. No axiom sweep or compilation was rerun in this blind pass; the author reports full validation separately and that evidence is not independently verified here.

The completed-table overlay is important: the finite engine samples a uniform full table `g`, then runs `fixedTableLoggedRun oa (completeTable cache g) cache`; it never regards cached cells as fresh randomness (`InitialCacheExpectedQuery.lean:167-170`). For each uncached `t`, the generalized key lemma proves a marginal factorization using invariance of whether the run ever queries `t` under replacing that cell (`ExpectedFreshQuery.lean:277-332`). The union lemma then turns the per-key inequalities into the expected sum. In the arbitrary-domain step, `smallBad` evaluates `bad` on a completed full extension, and `completeTable_extend_restrict` aligns the small and full overlays (`InitialCacheExpectedQuery.lean:253-284`). I find no missing premise or reversed inequality in these bridges.

The theorem deliberately does not bound an event caused solely by a bad initially cached answer. If a run has no initially uncached query, the trace premise cannot hold for a positive-probability bad output. An application must either prove a fresh-key witness for that output or separately charge the initial-bad event. This limitation appears explicitly in the new module docstring and is faithful to the contract; it is not hidden in the charge definition.

The strongest credible simplification would have generalized the existing finite empty-cache theorem in place and derived both public statements there. The change uses that approach for the key-specific lemma, then places the arbitrary-domain restriction and new public charge definitions in a separate 313-line module. The finite restriction theorem and empty-cache corollary are substantive boundaries; this is not a duplicate of the entire old proof. Root umbrella import includes the new module (`VCVio.lean:316`).
